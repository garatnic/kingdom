# 13 保存・性能・テスト — 詳細版 v0.5
> **確定**：ゲームを閉じた間は進行しない。保存方式、間隔、上限は**暫定**。

## 保存方式
IndexedDBに世界スナップショットを保存。自動保存は現実60秒ごと、手動保存は明示操作。正常世代を3つ保持し、保存中断でも直前の正常世代を維持。JSONエクスポート/インポートに対応する。

## スナップショット形式
```js
{
 schemaVersion:1, saveId:"save:123", createdAtIso:"2026-11-21T00:00:00Z",
 checksum:"sha256:...", world:{
   seed:1234, rngState:[], worldTimeTick:123456,
   speed:1, tickRemainder:0, idCounters:{citizen:13,event:42},
   terrain:[], citizens:[], settlements:[], nations:[],
   resourceNodes:[], stockpiles:[], constructionSites:[],
   inTransit:[], reservations:[], monsters:[], quests:[],
   researchStates:[], historyEvents:[], eventSequence:42
 }
}
```
日時は保存メタデータであり、ロード後のゲーム進行には使わない。チェックサムは正規化したworld部分のバイト列に対して計算。インポート時はサイズ・schemaVersion・必須フィールド・数値範囲・ID参照を検証。

## 保存処理
1. シミュレーション刻みの境界で読み取り一貫性のある状態を取得。
2. スナップショットを検証、シリアライズ、チェックサム計算。
3. IndexedDBの新規レコードへ書込み。
4. トランザクション成功後に `latestSaveId` を切替。
5. 正常な旧世代が3つを超えた場合のみ最古を削除。
エラー/容量不足/タブ終了時は `latestSaveId` を更新しない。保存に失敗した場合はUIに明示し、手動エクスポートを案内。

## ロードと移行
- 新しいセーブを別の一時オブジェクトへ復元し、参照整合性を検証してから現在の世界と置換。検証失敗時は元の世界を維持。
- `schemaVersion` ごとに `migrateV1ToV2` のような純関数を用意。未知の新バージョンは読み込まず、元ファイルを保全。
- 保存対象：03の時間・乱数状態、04の全人物/家系、05の現物/予約/輸送中、06の国家/開拓隊、07の魔物/依頼、08の研究、09の歴史、11のカメラモード/位置（自動追跡中の経過実秒は復帰時リセット）。
- 索引・スプライトキャッシュ・描画用座標は再構築可能な派生データとして原則保存しない。

## 遠景ハイブリッド処理【将来】
Ver.0.1の64×64固定マップでは全住民を詳細AIで更新する。**近景/遠景の切替実装は将来**。将来版では世界をチャンク/集落単位に分割し、カメラ周囲2チャンクを詳細、遠方は集落単位の集約更新を暫定推奨。
- **重要な不変条件**：住民ID、親子関係、人口、資源現物総量、国家所属、重要イベントはLOD切替前後で一致。
- 遠景では住民の描画/歩行経路のみ省略し、個人の出生死亡・婚姻・功績は集約結果を個人IDへ割り当ててから履歴に記録。人口だけ増やして架空の人物IDを作らない。
- 遠景の生産・消費は集落台帳で一括計算し、個人の所持資源との二重計上を禁止。詳細化時に現物と予約・輸送状態を復元する。
- 遠景中の魔物襲撃や国家滅亡は重要イベントとして処理し、カメラ追跡候補にできる。
- 詳細→遠景→詳細の変換関数はシード固定で再現可能にし、切替のたびに人口・資源が増える不具合を検出する。

## 性能【暫定】
PC60fps描画を目標、Ver.0.1は詳細住民100人程度。AI更新を個体IDで分散、経路探索の同時実行数を制限、スプライトをキャッシュ、画面外描画を省略。負荷過多時は描画品質を落としても、資源・出生・死亡などの論理更新を間引かない。タブ非表示時は停止、復帰時に壁時計経過を加算しない。
